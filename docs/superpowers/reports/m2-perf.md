## 一、§18.3 预算表逐项判定

预算原文：「活动实体 ≤300、同屏弹幕 ≤500、draw call ≤150（全图集）、逻辑帧耗时 ≤6ms、渲染 ≤10ms。超预算先降粒子再降实体。」判定口径：采样窗平均值对预算线（≤ 通过）。两轮窗口运行结论一致。

运行实证：三轮（两轮窗口 + 一轮无头）节流窗 steps/frame = 1.00–1.92（窗口运行 1.00–1.02），窗口运行 TIME_FPS = 60.0（1s 粒度）——生产节奏 60fps 成立。

**总结论：逻辑 / 实体 / 弹幕 / 60fps 能力全达标；draw call 在 F2（A2 暗视野+剪影）超标 ~8%，且全部层的 max 样本（191–270）都越线——预算的「全图集」前提当前美术管线未达成，属结构性缺口（见超标预案）。**

## 三、超标项与风险预案

**F2 draw call avg 162.6/159.7 > 150（超 ~8%），两轮复现，判定 FAIL。**

归因：F2 与 F1 同模板同注入，差值 ~+38 draw 稳定来自 A2 生态特效（`set_biome_a2`：暗视野组件 + 逐敌剪影 + 冰面），即每敌一次额外 draw 的 O(n) 结构。全部层 max 样本 191–270 越线还叠加瞬时 UI/特效（伤害数字、火雨警示圈）——当前美术为逐纹理精灵，§18.3「全图集」前提未达成。

按卡面预案顺序评估（不自行改产品代码）：
1. **降粒子**：F2 超标源是剪影/暗视野 draw，非粒子，此项缓解无效。
2. **降实体**：实体账目 67/300 仅占预算 22%，降实体对 draw call 收益不成比例且伤害压测强度，不采用。
3. **上报编排者**：✔ 本项 FAIL 上报。结构性解法归属后续卡（均非本卡可动产品代码）：a) 全图集合并（预算前提本身，收益覆盖全层含 max 尖峰）；b) A2 剪影批处理/材质合并（消 O(n) 逐敌 draw）；c) 暗视野遮罩 draw 合并。建议与 T34 真机复测联动后重跑本探针。

## 四、无头环境对照（披露用）

`--headless` 运行：渲染指标为 0（Dummy RenderingServer），节流窗墙钟失真（整帧 20.8–23.5ms、TIME_FPS 14–56 波动、steps/frame 1.64–1.92）→ 合成 60fps 线在无头下无意义。仅逻辑侧可信：逻辑帧 avg 0.025–0.028ms（仍 PASS）。**本报告判定全部采用窗口运行数据；渲染帧耗时留 T34 真机复测。**

## 五、观察项（T4 评审移交）

- **A2 剪影/暗视野 O(n) 逐敌处理**：非热点。F2 对 F1 逻辑帧增量 +0.0004ms（+3%），渲染 CPU 增量 +0.0013ms（40+ 敌规模）；增量体现在 draw call（+38）而非 CPU 时耗。T26 密房规模上去后需复验。
- **每帧组查询/逐帧分配**：无分配风暴与泄漏证据。采样窗 `OBJECT_COUNT` 峰值 ~23.6k 三层稳定无增长趋势；`OBJECT_ORPHAN_NODE_COUNT` 峰值 0；全量 gdUnit 0 orphans 佐证。逐帧字符串分配（T1 修复后）无独立监视器，间接证据为 TIME_PROCESS 全程低平（~0.02ms）无 GC 样尖刺（F2 max 0.25ms 为剪影挂载窗，仍远低于预算）。
- **T1 ArtLookup 逐帧字符串分配修复**的回归证据同上（低平处理时耗）。

## 六、偏差与披露

1. **A2/A3 最密模板未合入基线**（T26 评审分支未合）：三层均回落 A1 池最密 `combat_a1_03`（密度 18 = 4 刷点 + 14 陈设 + 0 危险）。生态差异仍真实：floor_idx 驱动瓦片套件（cave/crystal/magma），F2 挂 `set_biome_a2` 全特效，F3 注入岩浆池×2+间歇泉+火雨×4。**A2/A3 模板密房待 T26 合并后复测**——`densest_combat_id` 按池自动升级，届时更新 `test_densest_*` 单测钉值。
2. **Performance 时间监视器单位实证为毫秒**（4.7.2）：文档标注 "seconds" 与实测矛盾（空场景窗口运行 `proc_avg=0.0193` 出现在 16.573ms 整帧墙钟内，若为秒则单帧 _process 耗时超墙钟，不可能）。预算线按毫秒判定。
3. **渲染侧口径**：GPU 逐帧耗时无公开 API 未采；渲染 CPU 侧 = `TIME_PROCESS + RenderingServer.get_frame_setup_time_cpu()`。且本机窗口运行经虚拟显示适配器（OrayIdd 远程会话），GPU 光栅化不代表真机；draw call 为 CPU 提交侧计数、有效。**渲染帧耗时的最终验收留 T34 真机复测。**
4. **压测注入器**：玩家 hp 抬至 9999（防接触/岩浆 DOT 死亡，保证负载恒定，不影响帧成本）；弹幕 0 伤害但走完整命中管线（伤害数字/白闪/音频事件全开 = juice 全开）；40 注入敌 `counts_for_wave=false` 不消费波次账目、不触清房。
5. **副作用**：压测跑图会累积图鉴进度（击杀走正常信号路径）并追加 telemetry.csv 行——正常现象；窗口运行使用真实 `user://save.json`（无头测试另有 `save_headless.json` 重定向，不受影响）。
6. **合成口径**：60fps 能力线 = 逻辑帧 avg + 不节流整帧 avg（生产 60fps 下每帧各发生一次：1 物理 tick + 1 渲染帧），非逐帧直接测量；节流窗 fps=60、steps/frame≈1 作运行实证。不节流窗墙钟受宿主负载波动（F1 10.5ms 与 F2 6.7ms 两轮反序），合成线按最差值 11.2ms 报告，余量 33%。
7. **弹幕 500 顶格为压测目标值本身**：预算线「≤500」与注入上限一致，该项 PASS 语义为「顶格负载下逻辑/渲染仍达标」，无自然玩法会长期满池（生产敌方发射节奏远低于此）。
